# Research: hosted in-app notification providers for Cadence

Answers the wayfinder ticket **Compare notification providers** (map: **Wayfinder: In-app Notifications**).
Scope is the in-app channel only. Email, push, SMS, preferences and digests are out of scope.

- **Checked:** 2026-11-13. Pricing pages change often. Re-check before you commit to a provider.
- **Method:** I read the official pricing pages, the official docs, and the npm registry (`npm view <pkg>`). I read Courier's published TypeScript types from the `@trycourier/courier-js@3.7.1` tarball. Third-party mirrors are labelled where I used them. Anything I couldn't confirm from a primary source is marked **UNVERIFIED**.
- **Cadence context:** `package.json` pins `react@^19.2.7`, `react-router@8.3.0` (the map says React Router 7, but the repo is on 8.3) and `tailwindcss@^4.1.13`. `react-router.config.ts` has `ssr: true`. The session stores a numeric `userId` (`app/lib/session.ts`). DevUI switches users by posting to `/api/switch-user` (`app/components/dev-ui.tsx`, `app/routes/api.switch-user.ts`). **Note:** the map points to `app/lib/mailer.server.ts` for the Postmark plus `.outbox/` pattern, but that file is **not in this repo** (on `main` or this branch). The "local fallback analogous to the mailer" idea has no existing code to copy yet.

## Per-provider detail

### Knock

- **Free tier:** Developer plan is $0, "up to 10,000" messages/month. Bounced or failed messages are not counted. Stored profiles are unlimited. No MAU cap is listed. Isolated environments are unlimited. The Feed API and prebuilt components are included. "No credit card required." The next tier, Starter, is $250/month with 50,000 messages, then $0.005 each. Source: https://knock.app/pricing (checked 2026-11-13).
- **React feed:** `@knocklabs/react` provides `KnockProvider` (props `apiKey`, `user={{ id }}`, `userToken`) and `KnockFeedProvider` (`feedId`). It also has `NotificationIconButton`, `NotificationFeedPopover` and `NotificationFeed` (`renderItem`, `renderHeader`). Styling comes from `@knocklabs/react/dist/index.css`, `--rnf-*` CSS variables and `rnf-*` classes, plus `colorMode="dark"`. https://docs.knock.app/in-app-ui/react/feed
- **Headless:** `useKnockClient()`, `useNotifications(knockClient, channelId)` and `useNotificationStore(feedClient)` give you `items` and `metadata.unread_count`. Headless use doesn't mark items as seen automatically. Call `markAllAsSeen` or `markAsSeen` yourself. https://docs.knock.app/in-app-ui/react/headless/feed
- **npm (2026-11-13):** `@knocklabs/react@0.15.1` peers on react `^17 || ^18 || ^19`, with optional peers `next` and `@tanstack/react-router`. React Router is not listed, which is fine because it's optional. `@knocklabs/react-core@0.17.1`, `@knocklabs/node@1.41.1`.
- **SSR:** The feed docs don't cover SSR. A changelog entry (https://knock.app/changelog/2025-07-02, seen only as a search snippet) says `@knocklabs/react` gained React Server Components support. **UNVERIFIED** for React Router SSR.
- **Server API:** Workflows are built in the dashboard and triggered by key. The request takes `recipients` (IDs or inline objects, so a user can be identified at trigger time), `data`, optional `actor`, `tenant`, `cancellation_key` and `settings`. An `Idempotency-Key` header dedupes for 24h. `settings.sandbox_mode` generates messages without delivering them to providers. https://docs.knock.app/send-notifications/triggering-workflows/api. I didn't see the exact Node method signature rendered on that page. It's presumably `knock.workflows.trigger(key, {...})` (**UNVERIFIED**).
- **Identity / auth:** Without enhanced security mode, "a request with your public key can act as any user". Enhanced security is off by default and recommended for production. When it's on, the backend signs an RS256 JWT (`sub` = user id) with the environment's signing key. `signUserToken(userId, { expiresInSeconds })` from `@knocklabs/node/lib/tokenSigner` defaults to 3600s. The SDK has `onUserTokenExpiring` for refreshing. Enhanced security can stay off in the development environment. https://docs.knock.app/in-app-ui/security-and-authentication
- **States:** seen (automatic), read, interacted (cell click), link_clicked (needs link tracking), archived. These can also be set through the message status API. https://docs.knock.app/send-notifications/message-statuses
- **Real-time:** Socket connection. Inactive tabs are auto-disconnected after 2000ms by default. https://docs.knock.app/in-app-ui/react/feed
- **Local dev:** Each environment has its own API keys and isolated users and messages. Workflows are committed in development and promoted to production. https://docs.knock.app/concepts/environments

### Novu

- **Free tier:** "10,000 workflow runs / month". The comparison table lists subscribers as unlimited. Two environments (Dev and Prod). Activity feed retention is 24 hours. "No credit card required". The Free plan lists "All channels: Email, In-app, …". Pro starts at $30/month (30,000+ runs; the table lists $1.20 per 1K extra). https://novu.co/pricing (checked 2026-11-13). A run is counted **per subscriber**: a trigger to one subscriber is one run, and a topic with 100 subscribers is 100 runs. A resolved subscriber is billed even if the notification is later filtered out. Sources: https://docs.novu.co/platform/concepts/trigger and the glossary (search snippets). **UNVERIFIED:** whether the free `<Inbox />` shows Novu branding. Pro lists "Remove Novu branding", which suggests Free has it.
- **React feed:** `@novu/react` 3.19.2 (peers react `^18 || ^19`) provides `<Inbox applicationIdentifier subscriberId routerPush={(path) => navigate(path)} />`, `Bell`, `Notifications`, `InboxContent` and `Preferences`. Styling goes through the `appearance` prop. https://docs.novu.co/platform/quickstart/react, https://docs.novu.co/platform/inbox/overview. `routerPush` hooks straight into React Router's `navigate`.
- **Headless:** `NovuProvider`, `useNotifications()` (notifications, isLoading, error, fetchMore), `useCounts({ filters: [{ read: false }] })` and `useNovu()` (`novu.notifications.read/archive`). Hooks update on real-time events. https://docs.novu.co/platform/inbox/headless-mode.md
- **SSR:** Not covered in the docs (**UNVERIFIED**).
- **Server API:** `@novu/api` 3.19.1: `new Novu({ secretKey }).trigger({ workflowId, to: { subscriberId, firstName, email }, payload })`. The subscriber is identified inline in the trigger. https://docs.novu.co/platform/sdks/server/typescript. Workflows can also be defined code-first with `@novu/framework`. The in-app step returns `subject`, `body`, `avatar`, `redirect: { url, target }`, `primaryAction` / `secondaryAction` and `data`. Only http(s) or root-relative `/` URLs are kept. https://docs.novu.co/framework/typescript/steps/inApp.md
- **Identity / auth:** Use any string `subscriberId`. Novu auto-creates unknown subscribers. Turn on HMAC in the In-App provider settings per environment. After that, the Inbox won't load without `subscriberHash = HMAC-SHA256(NOVU_SECRET_KEY, subscriberId)` as lowercase hex, computed on the server. https://docs.novu.co/platform/inbox/prepare-for-production
- **States:** seen (automatic when visible), read, archived. Primary and secondary actions carry an `isCompleted` flag. Seen versus read is from a search snippet of the Novu docs. Read and archive methods are confirmed in the headless docs.
- **Real-time:** Unread count and actions sync in real time. https://docs.novu.co/platform/inbox/overview
- **Local dev:** Dev environment with its own keys. **Keyless mode**: `<Inbox />` with no props works for trying the UI without an account (changelog dated 2025-05-29, https://novu.co/changelog/instant-lessinboxgreater-experience-keyless-mode/). I didn't verify its limits. Novu is also open source and self-hostable (**UNVERIFIED** in this pass; it's off-constraint anyway, since the map requires a hosted provider).

### MagicBell

- **Free tier:** Builder, $0/month, "1,000 Deliveries/mo.", "1 Project", "Unlimited Users", "All integrations". Each channel a user receives a notification on counts as one delivery. Startup is $249/month with 50,000 deliveries. https://www.magicbell.com/pricing (checked 2026-11-13). Neither the pricing page nor https://www.magicbell.com/inbox states outright that the inbox is on Builder (**UNVERIFIED**, but implied by "All integrations" and the free-plan FAQ). Credit card requirement isn't stated.
- **React feed:** `@magicbell/react` 1.14.0: `Provider token={USER_JWT}`, `FloatingInbox`, `Inbox` (`ItemComponent`, `onNotificationClick`), `InlineNotification`, toasts. Styling uses per-component CSS imports plus `--magicbell-*` variables. https://www.magicbell.com/docs/libraries/react
- **Headless:** `@magicbell/react-headless` 5.5.1 is still on npm (peers react `>=18.3.1`, modified 2026-05-22). The current React docs don't mention it, and I couldn't confirm whether it's deprecated (**UNVERIFIED**).
- **Server API:** `magicbell-js` 1.8.0: `new Client({ token }).broadcasts.createBroadcast({ title, content, actionUrl, category, topic, recipients: [{ externalId, email }], customAttributes, overrides })`. One broadcast fans out to one notification per recipient. No workflow is needed. https://www.magicbell.com/docs/libraries/magicbell-js
- **Identity / auth:** A user JWT is **required**. It's HS256, signed on the backend with the project Secret Key, with claims `user_external_id` and/or `user_email` plus `api_key`. https://www.magicbell.com/docs/api/authentication/user
- **States:** The Notification primitive lists unread, read and archived, plus `sent_at`, `read_at` and `seen_at` timestamps. https://www.magicbell.com/docs/primitive/notification. `archived_at` and `action_url` come from a third-party API mirror (qodex.ai) and the SDK's camelCase `actionUrl`.
- **Real-time:** "Notifications update live via WebSockets." https://www.magicbell.com/inbox
- **Local dev:** One project on free, and no sandbox or test mode documented. A separate project for dev would need a second account or a paid plan (**UNVERIFIED**).

### Courier

- **Free tier:** Developer, free, "10,000 sends per month". In-app counts as one send. Above 10k you move to Business: pay-as-you-go at $0.005 per send, and **every** send is billed, including the first 10k. "Sends from Test and custom environments count the same as Production." https://www.courier.com/pricing (checked 2026-11-13). The pricing page doesn't list Inbox, environments or log retention per plan (**UNVERIFIED** for Developer, though the docs treat Inbox as a standard channel).
- **React feed:** `@trycourier/courier-react` 9.3.5 (peers react `>=18`): `CourierInbox`, `CourierInboxPopupMenu`, `CourierToast`, `CourierPreferences`. Theme objects (`CourierInboxTheme`) and click handlers `onMessageClick`, `onMessageActionClick`. Inbox and Toast "render client-side only" (stated for Next.js). https://www.courier.com/docs/sdk-libraries/courier-react-web.md
- **Headless:** `useCourier()` returns `auth`, `inbox` (`feeds`, `totalUnreadCount`, `error`) and `toast`. Feeds and tabs are registered with `inbox.registerFeeds()`. https://www.courier.com/docs/sdk-libraries/courier-react-web-hooks
- **Server API:** `@trycourier/courier` 10.0.0: `client.send.message({ message: { to: { user_id }, template: "nt_…", data, routing: { method: "single", channels: ["inbox"] } } })`. Inline `content` also works. https://www.courier.com/docs/in-app/send-to-the-inbox.md, https://www.courier.com/docs/get-started/send-a-message.md
- **Identity / auth:** The backend **calls** `client.auth.issueToken({ scope: "user_id:<id> inbox:read:messages inbox:write:events", expires_in: "2 days" })`. Leaving out `expires_in` mints a token that never expires. The client then calls `signIn({ userId, jwt })`. The SDKs don't refresh tokens. https://www.courier.com/docs/in-app/authenticate-users.md. Because minting is a network call to Courier, our loader would depend on Courier being up, or would need caching.
- **States and actions (from `@trycourier/courier-js@3.7.1` `dist/types/inbox.d.ts`):** `InboxMessage` has `read`, `opened` and `archived` timestamps, `actions: InboxAction[]` with `href`, `content`, `data` and `action_id`, plus `data`. Client methods: `read`, `unread`, `open`, `click`, `archive`, `unarchive`, `readAll`, `archiveAll`, `archiveRead`.
- **Real-time:** Only after you call `inbox.listenForUpdates()`. Without it, the inbox "loads once and doesn't update". https://www.courier.com/docs/sdk-libraries/courier-react-web-hooks
- **Local dev:** Each workspace starts with Production and Test environments, each with its own keys. Mock keys simulate sends without hitting providers, but they're plan-gated (Enterprise or Business, depending on which page you read). From search snippets of https://www.courier.com/docs/platform/workspaces/environments-api-keys.

### SuprSend

- **Free tier:** $0/month, 10,000 notifications/month. In-app feed is included "with SuprSend branding". 30-day logs. "No Credit Card required". Essentials is $100/month with 50,000 notifications, then $2 per 1,000. No MAU limit is stated. The pricing table doesn't clearly show whether Free gets multiple environments. https://www.suprsend.com/pricing (checked 2026-11-13).
- **React feed:** `@suprsend/react` 1.5.0: `SuprSendProvider` (`publicApiKey`, `distinctId`, `userToken`, `refreshUserToken`) and `<Inbox />`. The Inbox has a `theme` and `themeType` (dark/light), replaceable `bellComponent`, `badgeComponent` and `notificationComponent`, and `notificationClickHandler`, `primaryActionClickHandler` and `stores` (tabs). https://docs.suprsend.com/docs/react-sdk.md, https://docs.suprsend.com/docs/react-in-app-feed.md. Its dependencies include `@emotion/react`, `react-markdown@6.0.3` and `react-popper`, which is extra CSS-in-JS weight alongside Tailwind (npm, 2026-11-13). The old `@suprsend/react-inbox` is end-of-support.
- **Headless:** `@suprsend/react-core` 2.4.0: `SuprSendFeedProvider`, `useFeedData()` (`notifications`, `apiStatus`, `pageInfo`), `useFeedClient()` (`markAsSeen`, `markAsRead`, `fetchNextPage`). https://docs.suprsend.com/docs/react-sdk-headless-feed.md
- **Server API:** `@suprsend/node-sdk` 1.15.1: `new Suprsend(key, secret).workflows.trigger(new WorkflowTriggerRequest({ workflow: slug, recipients: [distinct_id | inline], data }, { tenant_id, idempotency_key }))`. The idempotency key lasts 24h, and up to 100 recipients fit in one trigger. Workflows and templates are designed in the dashboard. https://docs.suprsend.com/docs/node-trigger-workflow-from-api.md
- **Identity / auth:** Users are identified by an immutable `distinct_id`. With enhanced security mode on, the backend signs an ES256 JWT `{ entity_type: 'subscriber', entity_id, exp, iat }` with a signing key from the dashboard. The docs recommend it for production and don't state the default. https://docs.suprsend.com/docs/client-authentication.md
- **States:** `seen_on`, `read_on`, `interacted_on`, `archived`. Click target is `message.url`, with buttons in `message.actions[].url`. https://docs.suprsend.com/docs/react-sdk-headless-feed.md
- **Real-time:** Socket feed. The `reachability` status reports ONLINE, CONNECTING, DEGRADED, AUTH_ERROR or OFFLINE. https://docs.suprsend.com/docs/react-in-app-feed.md
- **Local dev:** Accounts come with Sandbox, Staging and Production workspaces, each with its own credentials. Test Mode is available in Staging. How many workspaces Free gets isn't stated. From search snippets of https://docs.suprsend.com/docs/workspaces and https://docs.suprsend.com/docs/developer/test-mode.

## What this means for Cadence

- **Identity mapping:** All five key on a string ID we choose, so `String(user.id)` from the session works. Mint the token or hash in the root loader. Switching users in DevUI posts to `/api/switch-user` and redirects, so the next loader run mints a token for the new user automatically. Remount the provider with `key={userId}` so no feed state from the old user lingers. Knock, Novu and SuprSend let you skip signing in dev (enhanced security or HMAC off), but then the public key can read anyone's feed, so production must sign. MagicBell always needs a JWT. Courier always needs a minted token from its API.
- **Signing cost:** Novu (one HMAC call) and Knock (`signUserToken` helper) are the simplest local signing. MagicBell's HS256 and SuprSend's ES256 are local signing with `jsonwebtoken`. Courier needs a call to Courier on each mint (or a cache), which ties into the map's "Provider outage" question.
- **SSR:** None of the five document React Router SSR. Courier says its components render client-side only. Plan to render the feed only on the client (for example, after hydration) and confirm in a prototype.
- **Styling with shadcn/Tailwind:** Knock, Novu, Courier and SuprSend all document headless hooks, so the bell and list can be our own components. MagicBell's headless story is unclear right now.
- **Local fallback:** No provider gives a no-network mode we can run in tests, though Novu's keyless mode is closest for UI. The app still needs its own fallback when no key is set (the map's "Local dev & tests" item).
